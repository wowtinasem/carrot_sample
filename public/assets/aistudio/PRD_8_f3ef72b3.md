# 아이콘카페 신메뉴 홍보 페이지 PRD

## 1\. 목적

제주 구좌 유기농 당근을 사용한 신메뉴 ‘유기농 당근케이크’를 알리고, 아이콘카페 첫 방문 고객이 쿠폰을 받아 매장에서 케이크를 구매하도록 유도한다. 주 고객은 카페 근처 20\~30대 직장인과 원재료 및 단맛을 살펴 디저트를 고르는 고객이다. 모바일 화면을 우선 설계한다.

* 주 행동 버튼 — **첫 방문 쿠폰 받기**
* 보조 행동 — 전체 메뉴 보기, 매장 위치 확인
* 첫 방문 혜택 — 유기농 당근케이크 구매 시 아메리카노 1잔 무료
* 운영 확인 지표 — 쿠폰 발급 건수, 사용 완료 건수, 발급 대비 사용률. 테스트 쿠폰은 집계에서 제외한다.

## 2\. 고객 화면

|순서|구역|내용과 동작|
|-|-|-|
|1|상단|아이콘카페 브랜드명과 ‘메뉴’, ‘매장 안내’ 링크|
|2|첫 화면|케이크 단면 사진, 제목 ‘당근과 과일이 더해주는 은은한 달콤함’, 신메뉴명, 원재료 설명, 첫 방문 혜택과 주 행동 버튼|
|3|신메뉴 소개|‘제주 구좌 유기농 당근으로 만들었어요. 당근과 과일 본연의 달콤함을 한 조각에 담았습니다.’ 판매가가 입력되면 표시|
|4|기본 메뉴|커피와 논커피 4종씩. 사진, 메뉴명, 판매가가 확정된 경우 가격 표시|
|5|쿠폰 안내|‘쿠폰 받기 → 계산대에서 바코드 보여주기 → 케이크 구매 시 아메리카노 받기’. 첫 방문 조건과 적용 기간 표기|
|6|매장 안내|확정된 주소와 영업시간을 표시하고 지도 URL이 입력되면 ‘길찾기’ 제공|

모바일 첫 화면에서 메뉴명과 혜택, 버튼이 사진과 함께 보이도록 이미지 높이를 제한한다. 고객이 아래로 스크롤하면 쿠폰 버튼을 하단에 고정하되, 쿠폰 창이 열렸거나 첫 화면 버튼이 보이면 숨긴다. 사용을 마친 브라우저에서는 버튼을 ‘쿠폰 사용 내역’으로 바꾼다. 모바일 메뉴 카드는 2열, 넓은 화면에서는 4열을 기본으로 한다.

쿠폰 창은 혜택, 첫 방문 및 케이크 구매 조건, 유효기간, 바코드, 번호, ‘계산대에서 보여주세요’를 표시한다. 사용 완료·만료 화면에서는 바코드 대신 상태와 사용일 또는 만료일을 표시한다. 키보드로 열고 닫을 수 있게 하고, 닫으면 초점을 버튼에 돌려준다. 모든 화면 문구는 한국어로 제공한다.

## 3\. 디자인과 이미지

* 크림색 `#FFF9EF` 바탕, 밝은 민트색 `#DFF2E8` 보조 면, 당근색 `#F18A42` 포인트를 사용한다. 주 버튼은 짙은 녹색 `#1E5945`에 흰 글자를 쓰고, 본문은 짙은 녹회색 `#22372E`를 사용한다. 밝은 주황은 배경과 장식에 활용한다.
* 데스크톱 첫 화면은 왼쪽에 카피와 버튼, 오른쪽에 케이크 사진을 배치한다. 모바일은 사진 아래에 카피를 배치하고 신메뉴명과 혜택이 사진 크기에 밀리지 않게 한다. 케이크 단면이 이미지의 중심에 오도록 크롭한다.
* 사진은 자연광, 밝은 도자기, 크림색 배경으로 통일한다. 움직임은 가벼운 등장 효과만 쓰고 모션 감소 설정을 따른다.
* 첨부된 `iconcafe-menu-images.zip`을 풀어 이미지 9장을 사용한다. 케이크 사진은 첫 화면과 신메뉴 소개에 사용하고, 음료 사진은 해당 카드에 연결한다. 첫 화면 사진을 먼저 로드하고 메뉴 사진은 화면에 가까워질 때 로드한다. 크기를 예약해 화면이 밀리지 않게 한다.
* 이미지는 생성 시안이다. 특히 케이크 시안의 견과 토핑과 크림 층, 음료의 잔·가니시가 실제 제공 형태와 다르면 공개 전에 교체한다. 원재료 설명은 ‘제주 구좌 유기농 당근’으로 범위를 명확히 한다. 공개용 ‘무가당’ 또는 ‘설탕을 더하지 않았어요’ 문구는 크림, 과일 가공품 등 전체 레시피와 표시 적합성을 확인한 뒤 적용한다. 초기 공개 카피는 ‘당근과 과일 본연의 달콤함’으로 제안한다.

## 4\. 바코드 쿠폰

### 고객 발급

1. 고객이 ‘첫 방문 쿠폰 받기’를 누르면 서버에서 해당 행사 상태를 확인하고, 발급 가능한 경우 추측하기 어려운 고유 번호를 발급한다. 버튼 연타나 통신 재시도에는 같은 발급 결과를 반환한다.
2. 번호를 흰 바탕의 검정 **Code 128** 가로 바코드로 표시한다. 바코드 아래에 같은 번호를 읽을 수 있게 적고, 바코드 좌우에는 스캔에 필요한 여백을 둔다.
3. 고객 회원가입 없이 동작한다. 같은 브라우저에서 다시 열면 동일 행사 쿠폰과 현재 상태를 다시 보여준다. 고객의 브라우저 세션과 행사 조합에 발급 고유 제약을 적용한다.
4. 브라우저 데이터 삭제나 다른 기기에서는 동일 고객인지 식별할 수 없다. 첫 방문 여부와 고객 1인 1회 혜택은 계산대에서 직원이 확인한다. 시스템은 동일 쿠폰 번호의 사용을 전 기기에서 한 번으로 제한한다.

### 직원 사용 처리

1. 직원이 로그인 후 매장용 화면에서 화면 판독이 가능한 스캐너로 읽거나 바코드 아래 번호를 입력한다. 스캔은 상태 조회만 수행한다.
2. 화면에 혜택, 유효기간과 상태를 표시한다. 직원이 첫 방문과 케이크 구매를 확인한 뒤 \*\*‘사용 확정’\*\*을 누른다.
3. 서버는 직원 권한, 쿠폰 번호, 유효기간, 미사용 상태를 검사한다. 데이터베이스에서 미사용 상태인 한 건만 원자적으로 사용 완료로 변경하고 사용 일시와 처리 직원을 함께 기록한다. 두 직원이 동시에 처리하면 한 건만 성공한다.
4. 사용 완료된 번호와 그 번호를 담은 화면 캡처를 다시 제시하면 ‘이미 사용된 쿠폰입니다’라고 표시한다. 만료·번호 오류·권한 없음은 각각 안내한다.
5. 응답이 끊기면 같은 번호의 서버 상태를 다시 조회한다. 서버 확인이 불가능하면 혜택 처리 여부를 확정하지 않고 직원에게 재시도를 안내한다. 새로고침, 다른 직원 기기, 서버 재시작 뒤에도 사용 기록을 유지한다.

## 5\. 구현 요구사항

* 기존 프로젝트가 있으면 그 구조를 따르고, 신규라면 고객 페이지와 직원 화면, 서버 API, 영속 데이터베이스를 갖춘 웹앱으로 구성한다. 프레임워크와 호스팅은 기존 프로젝트 및 운영 환경에 맞춘다.
* 공개 화면 `/`, 직원 화면 `/staff/coupons`. 서버 기능은 쿠폰 발급, 고객의 본인 쿠폰 상태 조회, 직원 코드 조회와 사용 확정으로 구성한다.
* 캠페인 데이터에는 행사 ID, 발급 시작·종료 시각, 사용 종료 시각, 운영 상태를 저장한다. 쿠폰 데이터에는 행사 ID, 고유 번호, 익명 세션 식별자, 발급·만료·사용 시각, 처리 직원 ID를 저장한다. 사용 여부와 만료 여부는 서버 시각으로 판정하고 화면에는 한국시간을 표시한다.
* 직원 권한 검사는 서버에서 수행한다. 발급·조회 요청에는 적절한 호출 제한을 적용하고 공개 응답에 처리 직원 정보를 노출하지 않는다. 테스트와 실운영 데이터는 구분한다.
* 매장 정보, 메뉴·가격, 이미지 경로, 행사 날짜는 설정에서 바꿀 수 있게 한다. 가격과 매장 정보는 확인된 값만 노출한다. 행사 날짜가 비어 있으면 미리보기에서만 테스트 쿠폰을 사용하고 공개 화면에는 쿠폰 준비 중을 표시한다.

## 6\. 완료 기준

* \[ ] 휴대폰 첫 화면에서 신메뉴명, 첫 방문 혜택, 쿠폰 버튼이 보이고 메뉴 8종의 이미지 매핑이 정확하다.
* \[ ] 같은 브라우저에서 새로고침하거나 버튼을 연타해도 한 행사에 발급된 쿠폰 번호가 유지된다.
* \[ ] 실제 매장 기기에서 휴대폰에 표시된 바코드를 읽을 수 있고 수동 입력도 동작한다.
* \[ ] 스캔 후 취소하면 미사용 상태가 유지되고, 직원이 사용 확정하면 재조회 시 사용 완료로 표시된다.
* \[ ] 이미 사용한 바코드를 다른 기기에서 다시 읽어도 차단된다. 두 직원이 동시에 확정해도 성공은 한 건이다.
* \[ ] 만료·잘못된 번호·비로그인 요청·통신 오류의 상태와 안내가 일치한다.
* \[ ] 공개 전에 메뉴 가격, 매장 주소와 영업시간, 지도 링크, 행사 기간과 쿠폰 유효기간, 실제 제품 이미지와 표시 문구를 확인한다.

## 7\. Codex 작업 순서

1. 고객 페이지를 만들고 이미지 9장과 반응형 화면을 연결한다.
2. 쿠폰 저장소와 고객 발급 화면, 직원 로그인·조회·사용 확정 기능을 연결한다.
3. 테스트 행사로 모바일 표시, 스캔, 수동 입력, 동시 사용, 만료, 장애 복구를 검증한다.
4. 매장 정보와 운영 조건을 채운 뒤 공개 환경에서 매장 기기로 쿠폰 1건의 발급부터 사용까지 확인한다.
